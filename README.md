# クラフトコーヒー＆グッズ — ECサイト Webアプリケーション

Python、Django、PostgreSQLを使用して開発した、ポートフォリオ用のECサイトです。

商品閲覧から会員登録、カートへの追加、注文処理、注文履歴の確認まで、一連のECサイトの機能を実装しました。特に、注文処理におけるデータ整合性、ユーザーごとのアクセス制御、入力バリデーション、自動テストを意識して開発しています。

## アプリケーション概要

- **アプリ名：** クラフトコーヒー＆グッズ
- **開発目的：** Djangoを使用したWebアプリケーション開発の学習と、実装した機能・設計上の工夫を示すポートフォリオの作成
- **公開サイト：** https://django-ec-site-b8pb.onrender.com
- **ソースコード：** https://github.com/sheltiesoso/django-ec-site

## 主な機能

### 1. 商品一覧・詳細表示

- 商品一覧および商品詳細の表示
- 商品画像、価格、在庫数、商品説明の表示
- 在庫切れ商品の「SOLD OUT」表示
- 在庫切れ商品のカート追加ボタンの無効化
- 商品画像が未登録の場合の代替表示
- Django Adminによる商品情報の登録・編集・在庫管理

### 2. ユーザー認証

- ユーザー登録
- ユーザー名、メールアドレス、パスワードによる登録
- 登録後の自動ログイン
- ログイン・ログアウト
- Django標準の認証機能を利用したセッション管理
- ログイン状態に応じたナビゲーション表示の切り替え

### 3. ショッピングカート

- セッションを利用したカート管理
- ログイン前でも利用できるカート機能
- 商品の追加、数量変更、削除
- カート内商品の合計金額の表示
- 在庫数を超える数量の追加・変更をサーバー側で制限

### 4. チェックアウト・注文処理

- 注文データの作成
- 注文明細の保存
- 注文確定時の在庫数の更新
- 注文完了後のカートのクリア
- `transaction.atomic()` を利用したトランザクション管理
- 注文処理中に例外が発生した場合のロールバック
- 購入時点の商品価格を注文明細に保存する価格スナップショット

注文データの作成、注文明細の保存、在庫数の更新をトランザクション内で処理することで、途中でエラーが発生した際のデータ不整合を防ぐ設計にしています。

### 5. 注文履歴・アクセス制御

- ログインユーザー本人の注文履歴一覧
- 注文詳細の表示
- 注文番号、注文明細、購入時の価格、合計金額の確認
- 他のユーザーの注文情報への不正アクセスを防ぐアクセス制御

注文詳細の取得時に、注文番号だけでなくログインユーザーも条件に含めています。他のユーザーの注文番号を指定した場合は、`404 Not Found` を返す設計です。

### 6. 入力バリデーション・エラーハンドリング

- 郵便番号の入力チェックと形式の正規化
- ハイフンなしの7桁の郵便番号をハイフン付きの形式に変換
- 操作結果を伝えるフラッシュメッセージ
- 404 Not Foundおよび500 Server Error用のエラーページ

## 設計上の工夫

### 1. トランザクションによるデータ整合性の確保

注文確定時には `transaction.atomic()` を利用し、注文データの作成、注文明細の保存、在庫数の更新をまとめて処理します。

途中で在庫不足などの例外が発生した場合に処理全体をロールバックすることで、一部のデータだけが更新される状態を防ぎます。

### 2. ユーザー単位のアクセス制御

注文詳細の取得時に、注文番号とログインユーザーの両方を条件として指定します。

```python
get_object_or_404(
    Order,
    order_number=order_number,
    user=request.user
)
```

これにより、URLの注文番号を変更して他のユーザーの注文情報を取得しようとするアクセスを防ぎます。

### 3. セッションを利用したカート管理

カート情報をセッションで管理することで、会員登録やログイン前でも商品をカートに追加できるようにしています。

また、数量変更時にはサーバー側でも在庫数を確認し、不正な数量が指定されることを防ぎます。

### 4. 購入時点の価格の保持

注文明細に購入時の価格を保存することで、商品マスターの価格が後から変更されても、過去の注文金額が変わらないようにしています。

### 5. 自動テストによる品質確認

Djangoのテスト機能を利用し、モデル、ユーザー認証、カート、注文処理、アクセス制御などを検証するテストを実装しています。

## テスト構成

現在のテスト構成は、以下の機能を対象としています。

| 対象 | 主なテスト内容 |
|---|---|
| 商品（products） | モデルの文字列表現、在庫判定、商品表示、非公開商品の扱い |
| 会員登録（accounts） | 登録成功、自動ログイン、メールアドレスの必須チェック、パスワード不一致 |
| 認証（accounts） | ログイン成功・失敗、ログアウト |
| カート（orders） | 商品追加、数量変更、削除、合計金額の計算 |
| 注文処理（orders） | ログイン必須の制御、在庫更新、価格スナップショット、ロールバック |
| アクセス制御（orders） | 注文履歴のユーザー制限、他のユーザーの注文へのアクセス拒否 |

テストの実行コマンド：

```bash
python manage.py test
```

## ローカル環境での起動方法

### 1. リポジトリをクローン

```bash
git clone https://github.com/sheltiesoso/django-ec-site.git
cd django-ec-site
```

### 2. 仮想環境の作成と有効化

Windows PowerShellの場合：

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 3. 必要なライブラリをインストール

```bash
pip install -r requirements.txt
```

### 4. 環境変数を設定

`.env.example` を参考に `.env` ファイルを作成し、ローカルのPostgreSQL接続情報を設定してください。

例：

```dotenv
SECRET_KEY=your-secret-key-here
DEBUG=True

DB_NAME=ecommerce_db
DB_USER=postgres
DB_PASSWORD=your_password
DB_HOST=localhost
DB_PORT=5432
```

**注意：** 上記は設定例です。実際のパスワードや秘密鍵はGitHubに公開しないでください。

### 5. データベースの準備とマイグレーション

PostgreSQLで `ecommerce_db` データベースを作成した後、以下を実行します。

```bash
python manage.py migrate
```

### 6. 管理者ユーザーの作成（任意）

```bash
python manage.py createsuperuser
```

### 7. テストの実行

```bash
python manage.py test
```

### 8. 開発サーバーの起動

```bash
python manage.py runserver
```

ブラウザで以下にアクセスします。

- アプリケーション： http://127.0.0.1:8000/
- 管理画面： http://127.0.0.1:8000/admin/
